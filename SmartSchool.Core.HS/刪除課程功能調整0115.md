# 刪除課程功能調整（0115）

## 變更摘要
在「刪除課程」流程中新增檢查與處理：若該課程仍存在 **dc_bind_key（調代課對應）** 資料，刪除前需先提示使用者確認，**確認後系統將先刪除調代課對應資料，再刪除課程**（不再顯示第二次「確定刪課」確認）。

## 變更檔案與函式

### 1. QueryData.cs
- **函式**：`GetCourseDCBindCountByID(string CousreID)`
- **變更內容**：
  - 修正 `string.Format` 未帶入參數的問題，正確將 `courseId` 帶入 SQL 查詢
  - 新增 `int.TryParse` 驗證，當 `CousreID` 非整數時回傳 `-1`（查詢失敗）
  - 確保 SQL 查詢能正確執行並回傳調代課對應筆數

- **函式**：`DeleteCourseDCBindByCourseID(string CousreID)`（新增）
- **變更內容**：
  - 刪除指定課程的調代課對應資料（`dc_bind_key` 表中 `ref_course_id` 符合的記錄）
  - 使用 PostgreSQL `DELETE ... RETURNING id` 語法取得刪除筆數
  - 當 `CousreID` 非整數或發生例外時回傳 `-1`（刪除失敗）
  - 成功時回傳實際刪除筆數（>= 0）

### 2. Manage.cs
- **檔案路徑**：`CourseRelated/RibbonBars/Manage.cs`
- **函式**：`btnDeleteCourse_Click(object sender, EventArgs e)`
- **變更內容**：
  - 在修課學生人數檢查通過後，新增調代課對應筆數檢查
  - 當 `dcBindCount < 0` 時：顯示錯誤訊息並中止（保守策略）
  - 當 `dcBindCount == 0` 時：維持原本刪除確認流程（一次確認）
  - 當 `dcBindCount > 0` 時：
    - 顯示一次提示視窗（含筆數），詢問使用者是否仍要繼續刪除
    - 使用者選 `No` 時中止刪除流程
    - 使用者選 `Yes` 時：
      - **先呼叫 `QueryData.DeleteCourseDCBindByCourseID` 刪除調代課對應資料**
      - 若刪除失敗（回傳 < 0）：顯示錯誤並中止刪除課程
      - 若刪除成功（回傳 >= 0）：**直接刪除課程，不再顯示第二次「您確定將刪除此課程？」確認**
      - 記錄 Log 時包含已刪除的調代課對應筆數

## 行為規格

### 刪除流程順序
1. 檢查是否有選取的課程
2. 檢查修課學生人數（`attendCount > 0`）→ 若有學生，直接擋下並提示
3. **新增**：檢查調代課對應筆數（`dcBindCount`）
   - 若 `dcBindCount < 0`：顯示「無法確認調代課對應」錯誤並中止
   - 若 `dcBindCount == 0`：直接進入原本刪除確認（「您確定將刪除此課程？」）
   - 若 `dcBindCount > 0`：
     - 顯示一次調代課對應提示（含筆數）
     - 使用者選 `No`：中止刪除
     - 使用者選 `Yes`：
       - **先呼叫 `QueryData.DeleteCourseDCBindByCourseID` 刪除調代課對應資料**
       - 若刪除失敗（< 0）：顯示錯誤並中止
       - 若刪除成功（>= 0）：**直接刪除課程，不再顯示第二次確認**
4. 執行刪除並記錄 Log

### 提示訊息
- 調代課對應查詢失敗：「目前無法確認此課程是否存在調代課對應資料（查詢失敗）。為避免造成資料不一致，請稍後再試或請系統管理員確認資料庫狀態。」
- 調代課對應提示：「此課程尚有 {筆數} 筆調代課對應資料。\n若要刪除課程，系統將先刪除調代課對應資料，再刪除課程。\n是否仍要繼續？」
- 刪除調代課對應失敗：「刪除調代課對應資料失敗，為避免造成資料不一致，已中止刪除課程。」

## 風險/注意事項

1. **資料一致性風險**：為避免刪除課程但仍保留 `dc_bind_key` 資料造成調代課資料失效或不一致，系統會先刪除調代課對應資料，再刪除課程。

2. **SQL 注入防護**：`GetCourseDCBindCountByID` 與 `DeleteCourseDCBindByCourseID` 方法均使用 `int.TryParse` 驗證輸入，並將整數值直接帶入 SQL，應注意資料庫權限設定。

3. **錯誤處理**：
   - 當 `CousreID` 非整數時，`GetCourseDCBindCountByID` 回傳 `-1`（查詢失敗）
   - 當 `CousreID` 非整數或發生例外時，`DeleteCourseDCBindByCourseID` 回傳 `-1`（刪除失敗）
   - 當 `dcBindCount < 0` 或 `deletedDCBind < 0` 時，系統採保守策略，中止刪除流程

4. **確認機制調整**：
   - 當 `dcBindCount == 0`：維持原本一次確認（「您確定將刪除此課程？」）
   - 當 `dcBindCount > 0`：**僅顯示一次確認**（調代課對應提示），確認後先刪對應再刪課，**不再顯示第二次「確定刪課」確認**
